# 模板兼容性与适配说明

本文用于说明第三方旧模板接入本项目时需要检查和处理的问题，供模板维护者和站点管理员参考。

适用版本：PHP **8.5.12 及以上**，主程序应使用本仓库初始发布版或其后续版本。实际验证运行时为 PHP 8.5.12；未逐个验证所有更高版本。

以下已确认问题来自本次指定模板的代码检查和实际运行，不代表所有第三方模板都存在这些问题，也不代表所有模板已经兼容。这里的“原版模板”指未经适配的第三方模板包，并非官方原版 MacCMS10 程序。本次未在官方原版程序上进行对照测试。

## 使用结论

指定模板的修正版已通过本次主要页面和操作验证，但需要与更新后的主程序配套使用。只替换模板，不能获得公共脚本、订阅输出和 PHP 参数兼容修复。

本仓库不附带第三方模板修正版压缩包。本文记录适配方法，不应理解为直接下载主程序就包含了下述模板文件修改。其他模板应按实际代码和使用需求单独评估。

## 原版模板已确认的问题

### 分类参数中的字符串未加引号

部分地区筛选使用 `['area'=>大陆]` 等表达式。PHP 8 会将裸字符串作为常量处理，未定义时导致页面报错。

处理方法：将字符串明确写成 `['area'=>'大陆']`，同时检查其他地区、语言和分类参数。本次指定模板的动漫、综艺布局中相关写法已在独立修正版中处理。

### 分类编号固定绑定布局

模板将分类编号 1、2、3 固定对应电影、连续剧、综艺，其他分类进入动漫布局。新安装或重新导入分类后，编号可能不同，导致栏目标题或布局不匹配。

本次处理：按“电影、连续剧、综艺、动漫”的分类名称选择布局，其他名称使用通用列表布局。

仍需确认：改名后的分类、自定义分类和子分类是否符合预期。当前方案不是可配置的布局映射；需要自定义布局时，应另行适配，不能继续依赖某次安装的固定编号。

### 验证码控件与后台开关不一致

原登录、注册页始终显示验证码并执行空值校验。后台关闭验证码后，前端仍可能阻止提交。

处理方法：根据登录或注册验证码开关显示控件，只在控件存在时执行前端空值校验。后端验证码验证继续由主程序配置控制，不能通过删除后端验证来解决模板问题。

### 回车提交绑定到不存在的按钮

原登录、注册页将回车事件绑定到 `btnLogin`，实际提交按钮为 `btn_submit`。

处理方法：统一事件绑定与实际按钮标识。本次已通过源代码核对修复；回车交互未作为独立浏览器用例计入验证结果。

### 会员中心残留静态演示内容

原会员中心包含写死的演示账号、VIP 权限展示，以及缺少实际字段绑定的演示表单，容易被误认为当前会员信息或可用功能。

处理方法：移除演示区，保留后端返回的实际会员资料。若需要资料编辑或权限展示，应接入真实字段和权限逻辑，不能只保留静态页面。

### 失效脚本和图片引用

原会员公共文件引用了模板包中不存在的 `tab.js`、`jquery.superslide.js`、`jquery.lazyload.js` 和 `formValidator-4.0.1.js`，会员 Logo 也引用了缺失图片。

本次处理：移除上述失效脚本引用，保留系统所需脚本；会员 Logo 改为读取站点 Logo 配置。其他模板不能直接照搬删除清单，应先确认对应文件是否存在、是否仍被功能调用。

### 旧链接标签和地址拼接

原会员页脚使用旧式链接标签，推广链接强制拼接 HTTP 与站点域名，前台 Logo 额外添加斜杠。这些写法可能产生失效链接或错误图片地址。

处理方法：页脚使用当前 `mac_url()` 路由函数；推广链接使用统一绝对地址生成；图片使用 `mac_url_img`。正式站还需检查 HTTPS、子目录部署和外部图片地址。

## 主程序已经完成的配套修复

以下修改属于主程序，不应归为模板独有缺陷，已包含在本仓库的[初始发布版](https://github.com/niuniuizy8888/maccms10_niuniuzs/commit/b2beb8857b8311db15588282e146b62b81904701)中。

- **公共脚本中断：**浏览历史代码使用未声明变量，在严格模式下抛错，影响后续评论初始化。已补齐变量声明，并加入前端回归检查。
- **XML 声明误判：**模板引擎曾将 XML 声明误判为 PHP 标签。已调整处理顺序，保留对模板直接执行原生 PHP 的限制。
- **订阅依赖主题文件：**RSS 和 sitemap 改由系统标准模板输出，避免主题订阅文件缺失或旧写法导致异常。该输出路径不使用主题自定义订阅样式。
- **PHP 参数与缺省字段：**处理部分空数值参数和缺省字段，减少 PHP 8.5 类型错误或警告。

不要为适配旧模板而全局放开原生 PHP 执行。旧模板依赖的逻辑应在明确用途后改用受支持的模板标签或受控后端实现。

## 已验证范围

指定模板修正版的首页、分类、影片详情、播放、登录、注册、留言、评论 AJAX、RSS 和 Google sitemap，共 10 类页面检查通过。页面响应通过不等于页面内全部操作均已验证。

浏览器实际验证了会员登录、视频画面播放及时间推进、留言与评论提交后进入待审核状态，以及会员中心显示当前用户资料。

主程序配套验证涵盖全新安装、商店上报、同步与异步采集，以及代码回归和默认模板 HTTP 检查。这些属于主程序验证范围，不能替代第三方模板自身的功能验收。

## 尚需确认的事项

- **手机端与样式：**尚未完成多分辨率、多浏览器视觉验收。需要检查导航换行、长片名、会员表单和播放器宽度。
- **分类与数据边界：**需要补充自定义分类、空分类、缺少封面或演员、多播放线路、分页筛选和长文本检查。它们是待验证方向，不是已经确认的故障。
- **会员完整流程：**主程序注册流程经过 HTTP 验证，但指定模板未逐项完成所有注册交互、资料修改及密码修改操作。
- **站点实际配置：**正式站应检查域名、Logo、HTTPS、子目录和功能开关，不直接沿用测试配置。
- **外部播放资源：**样本视频播放成功不代表所有资源始终可用，资源服务器与解析服务变化需要单独排查。
- **旧前端依赖：**需要独立检查依赖版本、实际使用范围和维护状态。本次不是完整安全审计，不能据此宣称模板不存在安全问题。

支付、短信或邮件找回密码、第三方登录不在本次测试范围内。

## 模板侧改动位置

以下是本次指定模板独立修正版的相对路径，用于定位适配点；这些第三方文件未加入本仓库。

- `html/public/head.html`：前台 Logo 地址。
- `html/public/typezm.html`、`html/public/typezy.html`：地区参数字符串。
- `html/vod/type.html`：分类布局选择。
- `html/user/login.html`、`html/user/reg.html`：验证码开关、提交按钮和 Logo。
- `html/user/head.html`、`html/user/findpass.html`：Logo 引用。后者的图片调整不代表找回密码流程已经测试。
- `html/user/include.html`：失效资源引用。
- `html/user/index.html`：演示内容和推广链接。
- `html/user/foot.html`：页脚路由链接。

## 启用与验收步骤

1. 备份站点现有模板和配置，确认主程序包含配套修复，PHP 不低于 8.5.12。
2. 将适配后的模板安装到正确模板目录，避免多嵌套一层文件夹；在后台选择模板并清理模板缓存。
3. 核对分类名称、Logo、域名、会员开关和验证码设置。
4. 用正式配置检查首页、分类筛选、详情、播放、登录、留言评论和订阅；确认评论内容与当前影片一致。
5. 补充手机端及本站实际使用的会员操作验收。发现问题时切回备份模板，保留日志用于定位。

后续适配应区分主程序问题、模板问题和外部服务问题，并保留可复现的验收记录。
