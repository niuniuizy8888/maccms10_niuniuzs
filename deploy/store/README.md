# 商店部署与维护说明

本目录补丁用于独立商店服务，应应用到实际商店项目根目录，不要应用到 MacCMS 站点目录。下文 `/path/to/` 均为占位路径，执行前请替换为实际位置。

客户端安装上报默认开启；分类可选择不导入，采集接口、播放器、绑定和定时任务由后台按需配置。

## 自定义 API 入口

`custom-api-entry.patch` 涉及 `route/macinstall.php` 和 `model/cloud.php`：

- 登记时传递 `api_entry`，验证完整 PHP 文件名并保留扩展名及大小写。
- 拒绝路径、查询参数和非法字符，避免文件名被错误改写。
- 缺省或 `api.php` 沿用域名登记；自定义入口保存为“域名/入口文件名”，与 worker 的 URL 拼接逻辑兼容。
- 已登记过自定义入口的站点，应在后台重新“补登记”以更新回调地址。

### 部署与回滚

先将两个原文件备份到 Web 根目录以外，并记录对应版本和备份位置。在商店根目录执行：

```sh
patch --dry-run -p1 < /path/to/custom-api-entry.patch
patch -p1 < /path/to/custom-api-entry.patch
php -l route/macinstall.php
php -l model/cloud.php
php /path/to/tests/store-registration-regression.php /path/to/store
```

若提示补丁已应用，不要重复应用；若上下文不匹配，应先核对当前代码。回滚时恢复同一版本的原文件；若 PHP 禁用文件时间戳检测，需按部署方式刷新 OPcache。

### 验收要求

- 分别检查默认入口与自定义入口的安装登记、首次心跳及回调地址。
- 检查导入分类和不导入分类两种安装流程；确认安装不会自动配置采集接口、播放器、绑定或定时任务。
- 使用已获授权的正式资源接口验证异步任务，确认客户端收到推送及完成事件，入库记录有正确分类和播放地址。
- 函数回归应覆盖缺省、默认、自定义、大小写及非法入口；使用隔离环境，不写生产业务数据。

## 多页采集与停止续采

`stop-resume-lease.patch` 修改商店 `model/rsync.php` 和 worker `rsync_task/main.go`，需同时部署。

停止后立即续采时，如果旧 worker 仍在处理当前页，而新 worker 又认领同一任务，会导致重复处理或进度超出总页数。补丁要求原 worker 完成在途页及结束事件、释放占用后，任务才能重新排队。排队使用条件更新，重复启动不会重置执行中的任务；服务启动时清理已结束任务的旧占用。

在当前页未结束时立即续采或重采，会提示“任务仍在结束当前页或已被启动，请稍后刷新重试”。停止不撤销已完成入库，当前页可能先完成再停止。

### 部署与回滚

1. 将两个源文件及 worker 二进制备份到 Web 根目录以外，记录版本、属主和权限。
2. 在独立构建目录应用补丁，执行 `go test ./...` 和 `go build`。
3. 确认没有活动任务后停止服务，再替换 PHP、Go 源码及构建产物。
4. 保持二进制部署属主并设置 `0755` 执行权限，启动服务后检查状态。
5. 若需回滚，成套恢复 PHP 和 worker，并恢复二进制执行权限。

### 验收要求

- 多页任务完成后的页数与请求范围一致，没有失败页或重复完成计数。
- 停止后等待当前页结束，从正确断点继续；过早续采应被拒绝。
- 同一任务重复启动不会产生并行处理；完整重采从第一页开始。
- 对未变化的源数据重复采集后，不应产生重复影片记录，应检查记录标识、播放线路与内容更新行为。
- 执行 `php /path/to/tests/store-requeue-regression.php /path/to/store`，使用内存 SQLite 验证在途任务不可重排、断点保留、重复启动拒绝及完整重采归零。
- 验收后清理隔离环境并停用不再使用的站点登记。

## 升级配置

资讯接口需自行配置，安装包不预置采集任务。已有部署的自定义任务不会被程序主动删除；升级前应备份配置，并在后台清理不再使用的接口和任务。
